Borrower Truth: seven connected fraud checks for non-bank lending

Vedant Tigade · B.Tech, Manipal University Jaipur (2028) · Wells Fargo 2027 Technology Program Intern application · synthetic data · live demo and answer key: borrower-truth.vercel.app · code walkthrough on request

The problem, from Wells Fargo's own filings

Loans to non-bank financial firms are Wells Fargo's largest commercial category: $208.8B, 20% of all loans (10-Q, June 2026), with "a single fraud-related loss" there in Q1 2026. In 2025–26, borrowers of this type (Tricolor, First Brands, per the DOJ and SEC) used several tricks at once: collateral pledged twice, bad loans reported as good, lender money disguised as customer payments, fake invoices, hidden debt, shells, rigged financials. Each hides in a different place; one check reads one place.

What I built

  • Seven checks (Python, DuckDB), one per documented trick, feeding each other: a shell found by S6 widens the lien search (S5) and the payer check (S3).
  • Combiner: confidence comes from independent sources; verdicts come from auditable rules, not a model.
  • Case service (Java 21, Spring Boot): playbook fixes, drafted letters, one-click approval, audit log.
  • Decision replay: every verdict carries fingerprints of its inputs, rules and code; replaying the run gave 120 of 120 identical decisions.
  • Streaming (Kafka): a suspicious payer is flagged 24 ms after the payment lands, then bridged into the case.
  • Document model: Donut, fine-tuned on a free Kaggle GPU, reads invoices so S4 can compare the document with the data.
  • Operations: Airflow nightly job, Prometheus and Grafana, isolated checks, file quarantine, stale-cache fallback.
  • Investigator agent (Qwen3-8B, open model): read-only tools, drafts a memo; code drops lines that cite nothing, invent numbers or contradict the records. It never decides.

What a credit officer gets

Not a score but a solved case: what's wrong, the evidence chain, a verdict with confidence, a playbook fix and a drafted letter that asks and doesn't accuse. Nothing is sent until a person approves; "done" is refused before "approved". All 60 of the highest-priority tenth of the queue are real frauds, and 365 of 366 suggested fixes target a planted trick.

Honest limits

DataAll synthetic. It proves coverage of the documented tricks, not real-world rates. Real accuracy needs Wells Fargo data and model-risk review.
WorkloadAbout 30 in every 100 honest borrowers land in "worth a look": the real review cost, reported rather than hidden.
Weakest checkFinancials that don't fit: 62 of 65. One miss: a lien filed under an abbreviated name; matching since fixed.
ModelCompared only with its untrained base; no large-model benchmark yet. The second read cut false flags only from 17 to 15.
MarketVendors each cover one place (Setpoint, Quantexa, Wolters Kluwer); none publicly joins all seven, so this uses them rather than replacing them (research/COMPETITORS.md).
Not builtPartitioned storage (no gain at this scale), obligor confirmations, officer sign-in through a bank login. Line-by-line status in proof/AUDIT.md.
