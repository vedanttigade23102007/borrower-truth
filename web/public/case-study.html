Borrower Truth: seven connected fraud checks for non-bank lending

Vedant Tigade · B.Tech, Manipal University Jaipur (2028) · for any bank that lends to non-bank lenders, Wells Fargo as the worked example · synthetic data · live demo and answer key: borrower-truth.vercel.app · code walkthrough on request

The problem, from primary sources

Banks have lent $1.32T to non-bank lenders, 10% of all bank loans; banks over $100B hold about 86% (FDIC, Feb 2026). In the worked example, Wells Fargo, it is the largest commercial category: $208.8B, 20% of all loans (10-Q, June 2026), with "a single fraud-related loss" there in Q1 2026. In 2025–26, borrowers of this type (Tricolor, First Brands, per the DOJ and SEC) used several tricks at once: collateral pledged twice, bad loans reported as good, lender money disguised as customer payments, fake invoices, hidden debt, shells, rigged financials. Each hides in a different place; one check reads one place. Borrower Truth is a second pair of eyes next to covenants and field exams, not a fix for fraud.

What I built

  • Seven checks (Python, DuckDB), one per documented trick, feeding each other: a shell found by S6 widens the lien search (S5) and the payer check (S3).
  • Combiner: "likely fraud" needs one checkable fact or two independent sources about the same claim; verdicts come from auditable rules, not a model.
  • Case service (Java 21, Spring Boot): playbook fixes, drafted letters, one-click approval, audit log.
  • Decision replay: every verdict carries fingerprints of its inputs, rules and code; replaying the run gave 120 of 120 identical decisions.
  • Streaming (Kafka, optional): a suspicious payer flagged 24 ms after the payment lands, then bridged into the case (last run 11 Sep 2026, on earlier rules).
  • Document model (optional, off by default): Donut, fine-tuned on a free Kaggle GPU, reads invoices so S4 can compare the document with the data.
  • Operations: isolated checks, file quarantine, stale-cache fallback; Airflow, Prometheus and Grafana fit the platform a bank already runs (last run 11 Sep 2026).
  • Investigator agent (Qwen3-8B, open model): read-only tools, drafts a memo; code drops lines that cite nothing, invent numbers or contradict the records. It never decides.

What a credit officer gets

Not a score but a solved case: what's wrong, the evidence chain, a verdict with confidence, a playbook fix and a drafted letter that asks and doesn't accuse, sent only after a person approves. The top tenth of the queue was 60 of 60 real frauds; 427 of 429 suggested fixes target a planted trick.

Real data: 2.23M SEC ABS-EE loan records (28 pools, 22 lenders) set how honest auto loans behave; a benchmark that flagged 3 honest pools was dropped. Switching off the SEC-based checks loses 39 of the 248 caught frauds.

Honest limits

DataFrauds are planted. Honest auto-loan behaviour and the loan-tape thresholds come from real SEC data; the other checks are still set on synthetic books. It proves coverage of the documented tricks, not real-world rates. Tricolor's own deals were reportedly private (Rule 144A) and never filed ABS-EE.
